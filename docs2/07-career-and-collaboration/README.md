# 07 — Career & Collaboration

The skills that turn a good coder into a good colleague: reviewing, writing PRs/RFCs, talking to
maintainers, and interviewing. Because this repo is **synthetic** (no real maintainers, no history),
this whole module is a **simulated OSS workflow** — *you* role-play the contributor, the docs
role-play maintainer expectations. The habits transfer directly to a real team.

| File | What it builds |
| --- | --- |
| [01-code-review-mindset.md](01-code-review-mindset.md) | The five review questions + a repo-specific checklist + example comments. |
| [02-writing-prs-and-rfcs.md](02-writing-prs-and-rfcs.md) | A PR template, commit-message style, and a repo-tailored RFC template. |
| [03-maintainer-communication.md](03-maintainer-communication.md) | Asking well, repro reports, respectful disagreement — with templates. |
| [04-interview-prep-from-this-repo.md](04-interview-prep-from-this-repo.md) | The big one: graded interview questions grounded in this code. |

**The throughline:** every artifact you produce (a review, a PR, an RFC, an interview answer) is more
persuasive when it points at a specific anchor and names a trade-off. Vague is weak; concrete is
senior.
