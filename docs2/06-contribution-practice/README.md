# 06 — Contribution Practice

Tickets and projects to *build* judgment by doing. Sized from "first safe change" to "design a
subsystem."

> **Simulated OSS workflow.** This repo is synthetic — no real maintainers, no issue tracker. So you
> role-play the **contributor** and these docs role-play **maintainer expectations**: acceptance
> criteria, review questions, and "what gets it rejected" are written as a maintainer would. Open a
> scratch branch, do the work, and self-review against [07/01](../07-career-and-collaboration/01-code-review-mindset.md)
> and [07/02](../07-career-and-collaboration/02-writing-prs-and-rfcs.md). Do **not** edit product code
> to "answer" a drill in the other modules — these tickets are where code changes belong.

**Suggested progression:** finish 2–3 good-first tickets (build confidence + the test habit) → one
mid-level ticket (cross-layer) → read a senior project and write its RFC → one refactor kata. Every
ticket should ship with a test, because the repo has none (R-03) — your test is part of the
contribution.
